Model Choice · Foundation Models vs. Data-driven Model

범용 비전 AI 대신, 실측 데이터로 학습한 전용 모델을 씁니다

YOLOE, DINO-X, SAM 3, SigLIP2, OCR, MediaPipe는 각자 분야에서 뛰어난 모델입니다. 하지만 SPOT AI가 풀어야 하는 문제는 “토양 사진 한 장으로 수분율이 35% 이하인지 판정하는 것”이고, 이 정답은 프롬프트가 아니라 센서로 측정한 실제 수분율에 있습니다. 그래서 제품 환경에서 이미지와 수분율을 직접 수집하고, 그 데이터로 MobileNetV3-Small을 학습합니다.

Why Not · 3 Key Reasons

범용 모델을 쓰지 않는 세 가지 이유

target

1. 풀려는 문제가 다릅니다

범용 모델은 객체 탐지 · 분할 · 의미 비교 · 문자 · 동작을 다룹니다. SPOT AI는 고정된 화분 안의 흙이 Dry(≤ 35%)인지 Wet(> 35%)인지를 가르는 이진 분류이며, 판단 근거는 흙의 미세한 색 · 질감 차이입니다. “흙이 어디 있는가”는 이미 카메라 위치로 정해져 있습니다.

sensors

2. 정답은 실측 데이터에 있습니다

“젖은 흙”이라는 텍스트와의 유사도는 수분율 35%라는 수치 기준을 알지 못합니다. SigLIP2의 유사도 점수는 정답 확률도 아닙니다. 수분 판정은 정전식 센서로 측정한 Ground Truth로 학습하고 검증해야 하며, 이는 어떤 범용 모델을 써도 피할 수 없는 과정입니다.

developer_board

3. Edge 기기에서 돌아가야 합니다

추론은 Raspberry Pi 4 (CPU · 4GB RAM)에서 오프라인으로 실행됩니다. 대형 Transformer 기반 모델이나 클라우드 API 의존 모델은 지연 · 메모리 · 네트워크 · 비용 면에서 상시 동작하는 급수 장치에 맞지 않습니다. 경량 CNN은 ONNX로 변환해 기기 안에서 바로 추론할 수 있습니다.

“성능이 낮아서”가 아니라 “풀려는 문제와 동작 환경이 달라서” 채택하지 않았습니다. 마지막 행은 SPOT AI가 선택한 모델입니다.

범용 비전 AI 모델과 SPOT AI 선택 모델 비교
모델 핵심 목적 대표 출력 SPOT 과제(35% Dry / Wet)와의 관계 Raspberry Pi 4 Edge 적합성 판단
YOLOE 오픈 보캐뷸러리 객체 탐지 · 분할 Box, Mask 화분 · 흙의 위치는 찾지만 수분 상태는 판단하지 않음. 흙 위치는 고정 카메라로 이미 결정됨 소형 모델은 가능하나, 필요 없는 탐지 단계가 추가됨 미채택
DINO-X 범용 객체 인식 · 장면 분석 Box, Mask 등 복잡한 장면 분석용. 단일 화분 · 단일 클래스 판정에는 과한 기능 주로 API로 제공 · 네트워크 · 호출 비용 의존 미채택
SAM 3 프롬프트 기반 개념 · 객체 분할 · 추적 Mask, 추적 결과 흙 영역을 정밀 분할할 수 있으나, 분할 결과에 수분 정보는 없음. 고정 ROI Crop으로 대체 가능 대형 모델 · GPU 권장 · CPU 실시간 추론 부적합 미채택
SigLIP2 이미지 ↔ 텍스트 의미 유사도 임베딩, 유사도 “dry soil”과의 유사도는 35% 수치 기준과 무관하며, 점수가 정답 확률도 아님 Transformer 인코더 · CPU 부담 큼 미채택
OCR 이미지 속 문자 인식 텍스트, 문자 위치 흙 사진에는 읽을 문자가 없음. 센서 값은 화면이 아닌 신호로 직접 수신 경량 엔진도 있으나 쓰임새가 없음 해당 없음
MediaPipe 손 · 얼굴 · 자세 랜드마크 · 제스처 랜드마크, 제스처 사람 동작 인터페이스용. 자동 급수는 사용자 조작 없이 동작 Edge 친화적이나 과제와 무관 해당 없음
MobileNetV3-Small
SPOT AI 선택		 실측 데이터 기반 토양 수분 이진 분류 Dry / Wet 확률 제품 환경 이미지 + 센서 실측 수분율로 학습 · 35% 경계 구간 별도 검증 ImageNet 사전학습 경량 CNN · 160 × 160 입력 · ONNX로 기기 내 추론 채택

OCR과 MediaPipe는 단일 모델이 아닌 기술 분야 · 프레임워크이며, Edge 적합성은 모델 크기 · 버전 · 하드웨어에 따라 달라집니다.

Model Notes · 개발 목적과 미채택 이유

모델별 한 줄 정리

Open-Vocabulary Detection

YOLOE

텍스트 · 시각 프롬프트로 탐지 대상을 바꿀 수 있는 실시간 탐지 · 분할 모델입니다.

blockSPOT은 “무엇이 있나”를 찾을 필요가 없습니다. 카메라와 화분 위치가 고정되어 있어 흙 영역은 ROI Crop으로 충분합니다.

Universal Object Perception

DINO-X

개방형 환경에서 다양한 객체를 탐지하고 수량 · 영역을 분석하는 범용 비전 모델입니다.

block복잡한 장면 분석에 강점이 있지만 SPOT의 장면은 단순합니다. API 의존은 오프라인 상시 동작과 맞지 않습니다.

Promptable Segmentation

SAM 3

텍스트 · 점 · 박스 프롬프트로 이미지 · 영상의 개념을 픽셀 단위로 분할 · 추적합니다.

block분할은 “흙이 어디인가”까지만 답합니다. 수분 판정은 결국 별도 분류 모델이 필요하고, 모델 크기는 Raspberry Pi에 부담입니다.

Vision-Language Embedding

SigLIP2

이미지와 텍스트를 같은 임베딩 공간에 두고 의미 유사도를 비교 · Zero-Shot 분류합니다.

block언어로 표현된 “젖은 흙”과 수분율 35%라는 수치 경계는 다릅니다. 실측 라벨로 학습한 분류기가 더 직접적입니다.

Text Recognition

OCR

문서 · 사진 속 문자를 텍스트로 변환합니다 (PaddleOCR, EasyOCR, Tesseract 등).

block흙 이미지에는 문자가 없고, 토양 수분 센서 값은 장치에서 직접 읽기 때문에 문자 인식 단계가 필요 없습니다.

On-device Perception

MediaPipe

손 21개 랜드마크 · 제스처 · 얼굴 · 자세를 실시간 추적하는 ML 솔루션 프레임워크입니다.

block사람의 동작이 아니라 식물과 흙을 봅니다. SPOT은 사용자 조작 없이 자동으로 급수합니다.

build

개발 단계 보조 도구로는 활용할 수 있습니다

  • checkYOLOE · SAM 3 — 수집 이미지에서 화분 · 흙 영역 Mask를 만들어 ROI 기준을 정하거나 라벨링을 보조
  • checkSigLIP2 — 대량 수집 이미지에서 흔들림 · 이물질 등 이상 이미지를 검색해 데이터 정제
  • checkDINO-X — 다양한 화분 · 배경 조건의 데이터 분포 점검

PC · 서버에서 1회성으로 사용 · 제품 기기에는 탑재하지 않음

flag

제품에는 실측 데이터로 학습한 경량 모델을 탑재합니다

  1. 제품 환경 토양 이미지 촬영
  2. 정전식 센서로 같은 시점 수분율 측정 (Ground Truth)
  3. MobileNetV3-Small 전이학습 · Fine-tuning
  4. 처음 보는 화분 · 35% 경계 구간 검증
  5. ONNX 변환 · Raspberry Pi 4 기기 내 추론

info결론적으로 여섯 기술은 “무엇이 어디에 있는가”를 잘 푸는 상호 보완적 도구입니다. SPOT AI의 핵심 질문인 “이 흙의 수분율이 35% 이하인가”는 실측 데이터로 학습한 전용 모델이 가장 직접적이고 가볍게 답할 수 있습니다.
